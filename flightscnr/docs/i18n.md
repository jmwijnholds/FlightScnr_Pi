# FlightScnr Pi translations

FlightScnr Pi uses validated JSON catalogs so the Python display and browser
portal consume the same effective messages without an additional runtime
dependency. English is the canonical catalog and the fallback for every
missing, invalid, or unavailable translation.

## Package layout

Each firmware-shipped locale lives under `flightscnr/i18n/locales/<locale>/`:

```text
manifest.json
messages.json
```

Locale identifiers use normalized BCP 47-style tags such as `nl`, `de`, or
`pt-BR`. Schema version 1 supports left-to-right languages only. Packages are
discovered from the shipped locale directory; arbitrary uploaded packages are
not loaded.

The manifest records the file schema, locale identity, display names, fallback,
English catalog revision, license, and translation authors. Translation packs
are adaptations of FlightScnr Pi and must remain under CC BY-NC-SA 4.0 with
appropriate attribution. Commercial use is prohibited without separate
permission from the original project author.

Only catalogs shipped in the firmware repository are discovered. The portal
does not accept catalog uploads, and OTA installs do not copy language files
into the writable data directory. Add or update a catalog through a reviewed
pull request so normal OTA integrity and rollback behavior remain unchanged.

## Message rules

- Add every source message to the English catalog first.
- Use flat semantic keys such as `weather.code.1000`; do not use English prose
  as a key.
- Keep named placeholders unchanged. For example, `Day {number}` may be
  reordered but `{number}` must still be present with the same spelling.
- Catalog messages are plain text, not HTML. Markup, control characters,
  positional placeholders, attribute access, and index expressions are
  rejected.
- Missing keys and invalid individual translations use the English value.
- Unknown keys are ignored. A broken manifest, invalid JSON root, unsupported
  schema, or unsafe package is skipped as a whole.
- Change a message key when its meaning or placeholder contract changes.
  Additive English messages increment `source_catalog_revision`; a file-format
  change increments `schema_version`.

Version compatibility is deliberately one-way. A pack on the current or an
older source revision loads, with English filling keys it does not contain. A
pack targeting a newer English revision is skipped because the older runtime
cannot verify its contract. An unsupported schema version is also skipped.
Never lower either version number.

The loader applies size, key-count, message-length, path, and placeholder
limits. It validates a replacement catalog before atomically swapping it and
retains the last-known-good catalog when refresh fails.

## Language and regional settings

`display_language` stores the requested UI language. `en` is the default.
`system` is an explicit option and resolves an administrator override or
`/etc/default/locale`; it is not the default. `LC_TIME` never determines the UI
message language and the application never calls process-global
`locale.setlocale()`.

Language is deliberately independent from the existing `date_format` (`us` or
`eu`), 12/24-hour clock, temperature, and distance/speed unit settings. Existing
installations therefore retain their current formatting and unit choices.

Language changes activate an immutable, already validated catalog and redraw
presentation state. They do not invalidate the semantic weather cache or call
Tomorrow.io. Catalog replacement is built off-lock and swapped atomically;
readers retain the last-known-good state if validation fails.

## Adding a language

1. Copy the English manifest and catalog into a new normalized locale directory.
2. Set the native and English language names, locale, authors, and current
   `source_catalog_revision`.
3. Translate values only; keep keys and placeholder names unchanged.
4. Run the i18n tests and the full FlightScnr test suite.
5. Verify the round 720x720 display and portal with a native speaker, including
   long strings, accents, fallback behavior, and a live language switch.

The `authors` array must identify the translator or native reviewer before a
catalog is released. Machine-assisted draft translations are not sufficient
review evidence. Include screenshots of the device picker, clock/forecast, and
portal; list the reviewer and test hardware in the pull request.

Prefer one data-only pull request per language so attribution and native-language
review remain clear.
